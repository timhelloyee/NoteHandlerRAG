# AA 競程整理的常見 Bug 列表

- 選手永遠會犯的幾種類型的錯誤及檢查方式：

1. 該宣告成 long long 的變數宣告成 int
   - 使用 `#define int long long` 試試看是否能通過
2. 陣列開太小、用到負數索引值
   - 把所有陣列大小都開到盡量大試試看
3. 忘記初始化或初始化成錯誤的值
   - 對於每個變數都重新想清楚初值應該是什麼，初值設置的正確嗎？
4. 整數溢位
   - 對於所有出現運算的地方都想想看會不會溢位，尤其是乘法

- 可先測試極端狀況

5. 特例情形沒處理好！
   - 測試輸入的值在極小極大值是否與預期一樣
   - 測試的資料要進入所有的 if else 的分支
6. 小於等於打錯、迴圈枚舉的範圍寫錯，差了 ±1
   - 實際模擬剛剛好在邊界的測試資料，看看是否會符合預期
7. 編號 1 至 n 和 0 至 n-1 搞混
   - 檢查所有和編號有關的地方

- 不要只會盯著程式碼看，要去尋找會錯的測試資料！
- 找到錯誤的測試資料後，模擬自己的程式碼，並印出過程中每個變數的值，看看從哪一步開始計算結果與預期不符
- 就算輸出的結果正確，也可以印出過程檢查是否符合預期！
